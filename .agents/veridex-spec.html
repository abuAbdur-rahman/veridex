Colors & Fonts

The foundation everything else in Veridex is built on. Two independent color systems — status and accent — plus a two-font type system split by role: written by a human, or structured data.

01 · Colors 02 · Fonts 03 · Pairing rules
01

Color system

Two systems, kept deliberately separate. Status colors describe a fact about a ticket. Accent describes what's interactive right now. A card can be both at once — they never merge into one color.

The rule: status answers "what is this ticket." accent answers "what can I do right now / what did I just click." Never merge them — a card can be pending (amber tag) and selected (orange fill) at the same time, as two independent facts.

Don't: reuse pending-amber as a hover or selected-state color just because it's visually close to orange — it reads as a severity change, not an interaction.

02

Type system

JetBrains Mono + Inter. One rule decides which to use: if it's typed by a person, Inter. If it's structured or generated data, JetBrains Mono.

In context

TICKET-047 · Env: Safari 18 · macOS
Login button unresponsive on Safari
Clicking "Log in" after entering valid credentials does nothing on Safari 18. No console error. Reproduced on macOS Sonoma, not reproducible on Chrome or Firefox.
→

The rule: typed by a person → Inter. structured or generated data → JetBrains Mono. Mono makes data columns align and reads as "fact." Long paragraphs in mono get tiring — keep Inter for anything a person actually wrote.
