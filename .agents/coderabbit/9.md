## Actionable Findings (12)

### 1. Runtime `ws` dependency

- Severity: Major
- Category: Stability and availability
- Location: `apps/server/package.json:45`
- Finding: Production code imports `ws` directly in `apps/server/src/ws/broadcaster.ts` and `apps/server/src/ws/handler.ts`, but the package is listed under `devDependencies`. The transitive `@fastify/websocket` dependency is not directly resolvable with pnpm's isolated layout when `ws` is absent from runtime dependencies.
- Recommendation: Move `ws` to `dependencies`; keep `@types/ws` in `devDependencies`.
- Source: https://github.com/abuAbdur-rahman/veridex/pull/9#discussion_r3835825497

### 2. Broadcast comment mutations

- Severity: Minor
- Category: Stability and availability
- Location: `apps/server/src/routes/comments.ts:26-45`
- Finding: Comment create, update, and delete handlers do not broadcast comment mutations, and WebSocket issue events do not invalidate `issueCommentsQueryKey`. Connected clients can remain stale after comment changes.
- Recommendation: Add a comment event carrying the affected `projectId` and `issueId`; broadcast it after each successful mutation and invalidate the corresponding issue-comments query. Update and delete must obtain the issue identifier before broadcasting.
- Source: https://github.com/abuAbdur-rahman/veridex/pull/9#discussion_r3835825500

### 3. MCP lifecycle and tool schemas

- Severity: Major
- Category: Data integrity and integration
- Location: `apps/server/src/routes/mcp.ts:27-32`
- Finding: The manual MCP endpoint requires `id`, does not handle `initialize` or `notifications/initialized`, rejects notifications without an id, and advertises tools without valid `inputSchema` values. Standard MCP clients cannot complete the lifecycle or reliably consume `tools/list`.
- Recommendation: Support the initialize handshake and initialized notification, allow notification requests without `id` and return no response for them, and include a valid JSON Schema `inputSchema` for every advertised tool.
- Source: https://github.com/abuAbdur-rahman/veridex/pull/9#discussion_r3835825502
- MCP references: https://modelcontextprotocol.io/specification/2025-06-18/server/tools, https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle

### 4. Do not update the immutable issue identifier

- Severity: Minor
- Category: Data integrity and integration
- Location: `apps/server/src/routes/mcp.ts:241`
- Finding: The MCP `update_issue` handler passes the complete parsed input to `updateIssue`; because `updateIssue` spreads the input into the database update, the immutable `issueId` is also written.
- Recommendation: Pass only mutable fields (`title`, `description`, and `severity`) as the update payload while continuing to pass `input.issueId` as the issue identifier.
- Source: https://github.com/abuAbdur-rahman/veridex/pull/9#discussion_r3835825505

### 5. Preserve omitted MCP assignment lists

- Severity: Major
- Category: Data integrity and integration
- Location: `apps/server/src/routes/mcp.ts:263-281`
- Finding: `assignIssue` replaces all assignments. Defaults of `[]` make omitted `developerAssigneeIds` and `qaAssigneeIds` clear existing assignments for those roles.
- Recommendation: Remove the empty-array defaults from the MCP schema so omitted fields remain `undefined` and preserve existing assignments; keep explicitly supplied `[]` as “clear.” Leave REST route defaults unchanged.
- Source: https://github.com/abuAbdur-rahman/veridex/pull/9#discussion_r3835825508

### 6. Guard concurrent comment soft deletes

- Severity: Minor
- Category: Data integrity and integration
- Location: `apps/server/src/services/comment.service.ts:80`
- Finding: The delete update matches only `comments.id`. Concurrent deletes can both succeed, allowing the second request to overwrite the first `deletedAt` timestamp.
- Recommendation: Use one timestamp and add `isNull(comments.deletedAt)` to the update predicate.
- Source: https://github.com/abuAbdur-rahman/veridex/pull/9#discussion_r3835825509

### 7. Remove failed sockets from rooms

- Severity: Minor
- Category: Stability and availability
- Location: `apps/server/src/ws/broadcaster.ts:59-64`
- Finding: A caught `socket.send()` failure leaves the socket in `rooms`. If no later `close` event occurs, every broadcast retries the stale socket.
- Recommendation: Delete the failed socket from the room immediately and delete the room when it becomes empty; preserve close-handler cleanup.
- Source: https://github.com/abuAbdur-rahman/veridex/pull/9#discussion_r3835825517

### 8. Revalidate idle WebSocket connections server-side

- Severity: Major
- Category: Security and privacy
- Location: `apps/server/src/ws/handler.ts:86-152`
- Finding: Session and membership checks after connection depend on client `ping` messages. A silent client remains in the project room and receives issue events after its session expires or membership is removed.
- Recommendation: Add a server-controlled revalidation timer or connection expiry deadline, close invalid connections, remove them from the room, and clear the timer in the close handler. Add coverage for membership or session invalidation without a client message.
- Source: https://github.com/abuAbdur-rahman/veridex/pull/9#discussion_r3835825520

### 9. Catch rejected comment submissions

- Severity: Minor
- Category: Stability and availability
- Location: `apps/web/src/components/app/CommentThread.tsx:22-28`
- Finding: `onSubmit` can reject, while the form discards `submit` with `void submit(event)`. This creates an unhandled Promise rejection. The body should remain when submission fails so the parent can render the error.
- Recommendation: Catch the rejected submission in `submit`, clear the body only after success, and preserve the entered text on failure.
- Source: https://github.com/abuAbdur-rahman/veridex/pull/9#discussion_r3835825522

### 10. Refresh pending invites after creation

- Severity: Minor
- Category: Data integrity and integration
- Location: `apps/web/src/components/screens/TeamSettingsScreen.tsx:164`
- Finding: If the pending-invites query completes before `createTeamInvite`, the new invite remains absent until the 30-second stale window ends or another refetch occurs.
- Recommendation: Invalidate `["teams", teamId, "invites"]` after successful invite creation, matching the revoke mutation behavior.
- Source: https://github.com/abuAbdur-rahman/veridex/pull/9#discussion_r3835825530

### 11. Log unexpected MCP tool failures

- Severity: Trivial
- Category: Stability and availability
- Location: `apps/server/src/routes/mcp.ts:163-169`
- Finding: `errorMessage` correctly collapses unexpected exceptions to `"Tool execution failed"` for clients, but the original exception is not logged. Unexpected tool failures therefore leave no server diagnostic.
- Recommendation: Log non-`AppError` exceptions with `request.log.error` before returning the sanitized JSON-RPC response.
- Source: https://github.com/abuAbdur-rahman/veridex/pull/9#discussion_r3835825497

### 12. Explicitly project comment list fields

- Severity: Trivial
- Category: Data integrity and integration
- Location: `apps/server/src/services/comment.service.ts:24-31`
- Finding: `.select()` without a projection returns every `comments` column, including `deletedAt`, and any future column added to the table would be exposed through the frontend wire contract without review.
- Recommendation: Select only the fields required by the frontend response, excluding `deletedAt`, following the explicit projections used by `listApiTokens` and `listPendingInvites`.
- Source: https://github.com/abuAbdur-rahman/veridex/pull/9#pullrequestreview-4999954584
