### 1. `apps/server/src/db/migrations/0006_modern_richard_fisk.sql:4`

**Severity:** 🟠 Major | **Category:** Data Integrity & Integration | **Effort:** Heavy lift

**Backfill existing invite rows before enforcing the new columns.**

This migration fails on any installation that already has rows in `invites`, because `token_hash` and `token_prefix` are added as `NOT NULL` without values. Even if those columns were nullable, dropping `token` without a backfill would make existing invite links unusable.

Add the columns as nullable. Backfill both values with the same token derivation used by invite validation. Enforce `NOT NULL` and remove `token` only after the backfill completes.
