## Actionable Findings

### 1. PostgreSQL documentation baseline

- Severity: Minor
- Category: Maintainability and code quality
- Location: `.agents/veridex-backend-spec.md:16`
- Finding: Changed documentation disagrees between PostgreSQL 17+ and PostgreSQL 18.
- Recommendation: Use PostgreSQL 17+ consistently in the backend spec, server environment example, and server contributor guide.
- Source: https://github.com/abuAbdur-rahman/veridex/pull/1#discussion_r3789570903

### 2. Unused `PUBLIC_MCP_URL`

- Severity: Minor
- Category: Maintainability and code quality
- Location: `apps/server/.env.example:5`
- Finding: Server validates `PUBLIC_MCP_URL`, but runtime code does not use it; the web MCP screen uses a hardcoded endpoint.
- Recommendation: Remove it from environment validation and `.env.example`, unless runtime configurability is implemented.
- Source: https://github.com/abuAbdur-rahman/veridex/pull/1#discussion_r3789570906

### 3. Vitest coverage provider mismatch

- Severity: Major
- Category: Stability and availability
- Location: `apps/server/package.json:31`
- Finding: `@vitest/coverage-v8` is on major version 4 while Vitest is on major version 3.
- Recommendation: Align the coverage provider with Vitest 3.x, suggested version `^3.2.4`.
- Source: https://github.com/abuAbdur-rahman/veridex/pull/1#discussion_r3789570909

### 4. Database URL schemes

- Severity: Minor
- Category: Stability and availability
- Location: `apps/server/src/config.ts:61-62`
- Finding: `z.string().url()` accepts schemes unsupported by the PostgreSQL client.
- Recommendation: Accept only `postgres:` and `postgresql:` URLs and add rejection tests for unsupported schemes.
- Source: https://github.com/abuAbdur-rahman/veridex/pull/1#discussion_r3789570911

### 5. Unnecessary `default_role` rewrites

- Severity: Minor
- Category: Performance and scalability
- Location: `apps/server/src/db/migrations/0002_normalize_auth_users.sql:21-22`
- Finding: Migration updates every `auth.user` row, including already normalized values.
- Recommendation: Add an `IS DISTINCT FROM NULLIF(btrim(...), '')` predicate to avoid unnecessary row locks, WAL, and table bloat.
- Source: https://github.com/abuAbdur-rahman/veridex/pull/1#discussion_r3789570916

### 6. Unsafe issue-status enum recreation

- Severity: Major
- Category: Data integrity and integration
- Location: `apps/server/src/db/migrations/0005_awesome_mesmero.sql:1-10`
- Finding: Previous schema supports `closed`, but replacement enum removes it. Existing `closed` rows make casts fail and roll back the migration. Type changes also lack explicit enum-to-text conversions and safe default handling.
- Recommendation: Map `closed` to an approved lifecycle value or retain it, use explicit `USING column::text`, drop `issues.status` default before conversion, and restore the `backlog` enum default afterward.
- Source: https://github.com/abuAbdur-rahman/veridex/pull/1#discussion_r3789570920

### 7. Issue status schema drift

- Severity: Major
- Category: Data integrity and integration
- Location: `apps/server/src/db/schema/enums.ts:16-21`
- Finding: Initial persisted enum includes `closed`, while the current Drizzle enum excludes it.
- Recommendation: Include `closed` or add an explicit migration that converts existing values before changing the schema.
- Source: https://github.com/abuAbdur-rahman/veridex/pull/1#discussion_r3789570923

### 8. Plaintext invitation tokens

- Severity: Major
- Category: Security and privacy
- Location: `apps/server/src/db/schema/invites.ts:9-10`
- Finding: Redeemable invitation bearer tokens are persisted in plaintext.
- Recommendation: Store a unique token digest and digest supplied tokens before lookup. Regenerate the initial migration from the corrected schema.
- Source: https://github.com/abuAbdur-rahman/veridex/pull/1#discussion_r3789570925

### 9. `fromStatus` migration/schema mismatch

- Severity: Major
- Category: Data integrity and integration
- Location: `apps/server/src/db/schema/issues.ts:63`
- Finding: Migration `0005` changes `issue_status_history.from_status` to text, while Drizzle still declares it as `issueStatusEnum`.
- Recommendation: Declare nullable `text("from_status")` and update dependent types to accept historical status values.
- Source: https://github.com/abuAbdur-rahman/veridex/pull/1#discussion_r3789570929

### 10. Cross-project issue-tag assignments

- Severity: Major
- Category: Data integrity and integration
- Location: `apps/server/src/db/schema/tags.ts:21-34`
- Finding: Junction-table foreign keys prove that issue and tag rows exist, but do not prove they belong to the same project.
- Recommendation: Add `projectId` to `issueTags` and enforce composite foreign keys to both issue and tag project identities, or validate both identities transactionally before insert.
- Source: https://github.com/abuAbdur-rahman/veridex/pull/1#discussion_r3789570932

### 11. PostgreSQL exposed on all interfaces

- Severity: Major
- Category: Security and privacy
- Location: `compose.yaml:5-6`
- Finding: Local Compose publishes a known-credential development database on all host interfaces.
- Recommendation: Bind it to `127.0.0.1:${POSTGRES_PORT:-5432}:5432` and update the backend specification example.
- Source: https://github.com/abuAbdur-rahman/veridex/pull/1#discussion_r3789570934
